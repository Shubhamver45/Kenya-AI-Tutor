1. Project Objective: What We Built & Why

The goal of this project is to build an interactive, conversational AI learning assistant designed specifically for Kenyan upper primary and junior secondary students (Grades 4–7). Instead of acting as an unconstrained, generic chatbot, the assistant is built to help students truly understand their classroom material through natural language interaction, respecting their cognitive level and school constraints.

The 5 Core Architectural Guarantees:
  1. Correct & Easy to Understand: Explains complex concepts with simple, step-by-step reasoning and authentic Kenyan analogies (e.g., cutting a chapati to explain fractions; East African rainfall cycles in Social Studies).
  2. Appropriate for the Student’s Level: Bounded strictly to Kenyan Competency-Based Curriculum (CBC) upper primary cognitive levels, avoiding graduate-level academic jargon.
  3. Multi-Turn Conversational Consistency: Tracks previous conversation turns so students can ask natural follow-ups without repeating themselves.
  4. Honest Boundary Management: When a question falls outside syllabus scope or available information, the system explicitly admits uncertainty with zero hallucinations.
  5. Connectivity Resilient: Operates efficiently under intermittent school bandwidth, using edge caching and lightweight context payloads.

2. Kenya Context: Hierarchical Knowledge & Bilingual Tracks

Standard commercial LLMs fail in Kenyan schools because they are unaware of the official curriculum taxonomy set by the Kenya Institute of Curriculum Development (KICD). In this project, all knowledge is strictly structured in a deterministic hierarchy:

Grade / Class (4–7) → Subject → Strand → Substrand → Specific Learning Outcomes (SLOs)

Every ingested curriculum chunk in data/curriculum.json carries structured metadata attributes:

Attribute Description Project Implementation Example
Grade / Class Target cognitive level (4 to 7) Grade 6 (Upper Primary CBC)
Subject Official CBC learning area Science & Technology | Mathematics | English | Kiswahili
Strand & Substrand Official KICD curriculum domain Strand: Living Things | Substrand: Human Internal Organs
Curriculum Code Unique syllabus locator KICD/PRI/CBC/G6/SCI/STR-01/LO-03
Language Track Bilingual evaluation flag English (Academic) | Kiswahili (Lugha na Sarufi)

Dual-Track Language Strategy: Model selection cannot be based on general English benchmarks alone. The project incorporates two distinct evaluation tracks: an English track and an authentic Kiswahili track ensuring natural fluency in Sarufi (grammar), Nomino (nouns), and scientific body terminology (e.g., Ubongo, Mtima, Mapafu) without unnatural direct machine translations.

4. Query Understanding & Follow-up Context Rewriting

In school tutoring, students constantly ask short follow-up questions:

Turn 1: "What is a fraction?" → Tutor explains numerators and denominators.
Turn 2: "Can you give an example?"
Turn 3: "Why is the bottom number important?"

If Turn 2 ("Can you give an example?") is sent to a database search, standard keyword and vector retrieval return zero relevant results because the query contains no subject nouns.

How Your Project Solves This: In llm/client.py, the rewrite_query() function inspects the student's conversation history and reformulates the follow-up into a complete standalone search query:

"Can you give an example?" + History → "Give an everyday real-world example of fractions in Grade 6 Mathematics"

This ensures that conversational follow-ups never bypass curriculum retrieval. (Common greetings like "Hello" or "Habari" trigger an instant conversational fast-path without invoking retrieval).

5. Curriculum-Grounded Hybrid RAG & Reciprocal Rank Fusion

In retrieval/hybrid_search.py, the project implements a dual-pass search mechanism that keeps the AI strictly grounded in the official KICD syllabus:

  • 1. BM25 Lexical Keyword Search: Matches exact textbook keywords, specific mathematical formulas, and official KICD chapter codes.
  • 2. Dense Semantic Vector Search: Maps student phrasing, everyday descriptions, and conceptual synonyms into high-dimensional vector space.
  • 3. Reciprocal Rank Fusion (RRF): Merges the lexical and vector rankings using the formula:
    RRF(d) = Σm ∈ {BM25, Dense} 1 / (60 + rankm(d))
  • 4. Dynamic Grade Fallback: If a student has Grade 6 selected but asks a Grade 4 organ question, the retriever automatically falls back to search the entire curriculum library so the student receives an accurate, grounded answer rather than a blank error.

6 & 7. AI Orchestration Harness & 3-Layer Response Validation

To prevent hallucinations and guarantee safety, the project enforces a multi-tiered validation pipeline before any response reaches the learner:

Validation Layer Mechanism Latency Responsibility
Layer 1: Basic Checks Deterministic regex & safety filters < 5 ms Sanitizes inputs, enforces basic safety, redacts personal information.
Layer 2: Grounding Auditor Single-token logit verification (YES/NO) 400–800 ms Verifies whether the generated answer is 100% grounded in the retrieved KICD syllabus excerpt.
Layer 3: Bounded Auto-Correction Critique injection with retry 1,200–2,000 ms Executes only if Layer 2 fails: Generate → Validate → Correct → Respond.
Strict Bounded Retries: The retry loop is strictly capped at exactly 1 attempt. If an answer fails twice, the system gracefully admits uncertainty rather than risking a hallucination, keeping latency under 3.5s and token costs completely controlled.

8 & 9. Multimodal Input & Edge Connectivity Resilience

Multimodal Input (Section 8): When students take a photo of a textbook problem or chalkboard math, the image is processed via an isolated pipeline:

Student Photo → Vision / OCR Normalization → Structured Question Formulation → Standard RAG Pipeline

By decoupling vision understanding from retrieval, both text and camera inquiries share the exact same pedagogical reasoning and safety guardrails.

Edge Connectivity & Shared Devices (Section 9):

  • Site Edge Nodes: On-premise school servers cache common syllabus chapters and prompt embeddings locally over LAN, reducing uplink bandwidth by 65%.
  • Session State Preservation: During internet dropouts, active conversations are preserved in browser storage; events synchronize automatically upon reconnection.
  • Shared Computer Lab Isolation: Multiple pupils sharing the same computer lab workstation operate under distinct session tokens, preventing cross-learner history leakage.

Observability Spans 1 to 5 (Section 15)

Every transaction is instrumented across 5 OpenTelemetry execution spans:

  • Span 1 (Query Understanding): Tracks rewrite latency and intent classification.
  • Span 2 (Hybrid Retrieval): Measures BM25 scores, vector similarity margins, and chunk count.
  • Span 3 (Model Inference): Records prompt tokens, completion tokens, time-to-first-token, and throughput.
  • Span 4 (Validation Audit): Captures Layer 2 audit verdict (YES/NO), critique reasons, and retry counts.
  • Span 5 (Telemetry Totals): Records end-to-end latency and exact query financial cost.
