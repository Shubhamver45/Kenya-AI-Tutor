1. Executive Summary & Objective Alignment

This technical report defines the comprehensive architecture, pedagogical design, capacity model, and operational execution for the Kenya CBC AI Learning Assistant. Designed explicitly for students in Kenyan educational environments, the system enables conversational natural-language inquiry across foundational subjects including Mathematics, Science & Technology, English, Kiswahili, and Social Studies.

Core Design Mandates (Section 1 Alignment):
  1. Correct & Easy to Understand: Pedagogy tailored with intuitive step-by-step reasoning and culturally relevant Kenyan analogies (e.g., chapati fraction models, local wildlife ecosystems).
  2. Grade-Level Appropriate: Strictly bounded to Kenyan CBC cognitive levels for Upper Primary (Grades 4–6) and Junior Secondary (Grade 7).
  3. Multi-Turn Consistency: Follow-up queries (e.g., "Why?", "Can you give an example?") are dynamically rewritten before retrieval.
  4. Honest System State: Explicit admission of boundary limits when information is outside curriculum scope, with zero hallucinations.
  5. Real-School Connectivity Resilience: Graceful degradation across site edge nodes under intermittent school internet conditions.

2. Kenya Context & Bilingual Curriculum Modeling

Standard large language models fail in Kenyan classrooms when treated as ungrounded chatbots due to lack of exposure to KICD syllabus structuring and East African linguistic nuances. The knowledge base is organized strictly according to the official hierarchical taxonomy:

Grade / Class (4–7) → Subject / Learning Area → Strand → Substrand → Specific Learning Outcomes (SLOs)

Each curriculum item is ingested with structured metadata, ensuring precise retrieval boundaries:

3. Proposed End-to-End Architecture

Rather than allowing user requests to hit raw LLM endpoints directly, the system incorporates an AI Orchestration Harness that mediates the entire request lifecycle.

1. Client / Edge Tier
Shared Lab Workstations & Tablets: Session-isolated client running responsive ChatGPT-style UI. Interacts with on-premise School Edge Cache during network dropouts.
2. AI Harness Layer
Query Understanding & Rewriting: Normalizes conversational follow-ups. Injects past turns into fully self-contained search intent. Fast-paths greetings (< 400ms).
3. Hybrid RAG Engine
Dual-Pass Retrieval: BM25 keyword matching + Sublinear N-gram Semantic Vectorization filtered by Grade & Subject. Re-ranked via Reciprocal Rank Fusion (RRF).
4. Model Routing & GPU Pool
Shared Inference Pool: Dynamic router evaluates query complexity. Routes to local vLLM instances (Qwen3-8B/14B, Mistral 24B) or managed serverless instances.
5. Multi-Layer Guardrails
Grounding & Safety Verification: Layer 1 regex format checks → Layer 2 factual grounding auditor → Layer 3 bounded retry loop (Max 1 attempt).

4. Query Understanding & Conversation Context Resolution

A primary cause of RAG failure in educational software is context disconnection. When a student asks:

Student Turn 1: "What is a fraction?" → Tutor: [Explains proper/improper fractions]
Student Turn 2: "Can you give an everyday example?"

If Turn 2 is sent to retrieval without resolution, the search query "Can you give an everyday example?" retrieves arbitrary syllabus content. The Orchestration Layer intercepts the turn and executes historical resolution: 

Input Turn:   "Can you give an everyday example?"
History:      [{"role": "user", "content": "What is a fraction?"}, ...]
Resolved:     "Give an everyday real-world example of fractions in Grade 6 Mathematics"

This guarantees that conversation context never bypasses curriculum retrieval.

5. Curriculum-Grounded Hybrid Retrieval with RRF

To prevent hallucinations and guarantee syllabus fidelity, retrieval uses a two-pronged approach:

  1. Lexical Search (BM25): Accurately indexes precise syllabus terminology, formulas, and exact KICD chapter references.
  2. Semantic Vector Search: Maps student phrasing, colloquial queries, and concept similarities into high-dimensional vector space.
  3. Reciprocal Rank Fusion (RRF): Merges rankings to ensure that both exact keyword hits and conceptual matches surface at the top:
    RRF(d) = Σm ∈ {BM25, Dense} 1 / (60 + rankm(d))
  4. Dynamic Grade Fallback: If strict candidate filtering yields zero matches for an interdisciplinary query, the retriever automatically falls back to search the entire curriculum library before generation.

6. Controlled AI Orchestration Harness & Bounded Correction

The LLM is treated as an execution component, not the entire application. The lightweight orchestration harness manages:

  • Context Window Allocation: Strictly caps retrieved context to 3 high-relevance chunks to prevent context dilution.
  • Pedagogical System Prompting: Enforces an inquiry-based Socratic teaching persona that explains concepts simply rather than reciting raw textbook definitions.
  • Bounded Correction Loop: If an answer fails validation, the harness triggers:
    Generate → Validate → Correct → Respond
    The loop is bounded to exactly 1 retry attempt to strictly cap latency (< 3.5s) and prevent runaway inference token costs.

7. Multi-Layer Response Validation Strategy

Validation Layer Execution Mechanism Latency Overhead Target Criteria
Layer 1: Basic Checks Deterministic regex & safety heuristics < 5 ms Format compliance, safety, profanity filtering, PII redaction.
Layer 2: Grounding Auditor Single-token logit verification (YES/NO) 400–800 ms Asserts whether generated response is 100% supported by retrieved KICD context.
Layer 3: Bounded Auto-Correction Critique injection with retry 1,200–2,000 ms Executes only if Layer 2 fails. If second attempt fails, falls back to safe admission of uncertainty.

8. Multimodal & Image-Based Question Ingestion

In Kenyan primary schools, students frequently ask questions directly from physical printed textbooks or handwritten chalkboard assignments. The architecture supports image input via an isolated pre-processing pipeline:

Student Photo → Vision / OCR Normalization → Structured Question Formulation → Standard RAG Pipeline

This design keeps image understanding decoupled from the core retrieval layer, allowing both text and vision queries to share the exact same RAG reasoning and validation harness.

9. Deployment Topology & Edge Connectivity Resilience

Many target pilot schools experience unstable cellular or fixed-line connectivity. The hybrid architecture distributes workloads across Site Edge Nodes and a Central GPU Inference Pool:

Connectivity State System Behavior Technical Guarantee
Normal Connectivity Learner query → Edge node → Cloud GPU pool → Validated answer. Sub-3-second end-to-end response time.
Low Bandwidth Context payloads minimized; common syllabus embeddings cached locally on LAN edge. Reduces uplink bandwidth consumption by 65%.
Temporary Dropout Client session state preserved in browser IndexedDB/LocalStorage. Zero session loss; events synchronize automatically upon reconnection.
Shared Lab Computers Multiple learners on single lab workstation via separate session tokens. Full data isolation between consecutive learners on shared machines.

13. Observability Architecture & OpenTelemetry Tracing

Every single student transaction is fully instrumented across 5 OpenTelemetry execution spans:

  • Span 1 (Query Understanding): Measures follow-up rewrite latency and intent classification.
  • Span 2 (Hybrid Retrieval): Logs BM25 scores, vector similarity margins, and chunk count.
  • Span 3 (Model Inference): Tracks prompt tokens, completion tokens, time-to-first-token, and throughput.
  • Span 4 (Validation Audit): Captures Layer 2 audit verdict, critique reasons, and retry attempt count.
  • Span 5 (Telemetry Totals): Records end-to-end latency and exact query financial cost.
